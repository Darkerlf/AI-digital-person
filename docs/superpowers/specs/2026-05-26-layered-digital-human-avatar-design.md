# 数字人分层拟真表达重构设计

## 目标

在不采购实时数字人视频服务、不引入 Live2D 模型授权和不改变现有 TTS 接口的前提下，将当前半身 PNG 数字人重构为可稳定呈现语音、表情、口型同步的分层角色。第一阶段以本地动态样片验证视觉效果，通过后再接入微信小程序 AI 导游页。

## 已确认方向

采用 A 方案：精修分层立绘。

- 保持当前女性导游的人物身份、发型、服装与整体风格。
- 保留 `CosyVoice -> mouth_cues -> 小程序播放时间轴` 的现有语音同步链路。
- 不继续使用 `expr_smile.png / expr_enthusiastic.png / expr_thinking.png` 整图替换讲话状态，因为整图与基础图混合易发生脸部跳变和局部错位。
- 新的表情表现依靠同一基础图坐标系中的透明局部层叠加完成。

## 视觉资产结构

以 `base_halfbody.png` 为唯一恒定底图，在相同像素画布和锚点上增加透明 PNG 层：

| 图层 | 第一版内容 | 用途 |
| --- | --- | --- |
| 底图 | 原有基础半身图 | 保持人物一致性 |
| 眼部层 | 睁眼、半眨、闭眼 | 自然眨眼，避免 CSS 画眼造成违和 |
| 眉部层 | 自然、专注、温和上扬 | 思考和讲解情绪变化 |
| 嘴型层 | 静闭、轻闭笑、窄口、轻开、中开、大开、圆口、双唇闭合、带齿微笑 | 由发音 cue 驱动 |
| 可选修饰层 | 轻微面颊暖色或高光 | 仅用于热情欢迎状态，首版可不启用 |

所有局部层必须在同一个 `455 x 700` 坐标系导出，透明背景，仅变化目标五官区域；渲染时不通过缩放裁切补偿位置。

## 动作与状态设计

角色包含四种表现状态：

| 状态 | 表情 | 口型 | 微动作 |
| --- | --- | --- | --- |
| 待机 | 自然眉眼 | 静闭口 | 不规则眨眼、轻微呼吸 |
| 思考中 | 专注眉部 | 静闭口 | 一次缓慢点头，避免持续摇动 |
| 开始讲解 | 温和眉眼 | 随首段音频驱动 | 轻微抬头、微笑起势 |
| 持续讲解 | 自然/温和轮换 | 语音时间轴驱动 | 呼吸、偶发眨眼，避开大开口帧 |

口型沿用后端时间戳 cue 驱动，前端将现有五类映射扩展到视觉帧：

- `closed`：静闭口或双唇闭合，双唇音优先使用双唇闭合帧。
- `small`：窄口。
- `mid`：轻开口与中开口根据持续时间切换。
- `big`：大开口。
- `round`：圆口。
- 帧之间保持约 `65-90ms` 的视觉稳定窗口，以渐变位移或透明度过渡降低硬切感。

## 组件与数据流

动态样片先在独立本地预览中验证三种状态和口型时间轴，正式接入后改造 `miniprogram/src/components/DigitalHuman.vue`：

1. 后端 `/api/tourist/voice/tts-sync` 继续返回 `audio_url`、`duration_ms` 和现有五类 `mouth_cues`，接口不变。
2. `guide.vue` 继续负责播放进度、讲话/思考状态以及当前 cue，不承担图层组合细节。
3. `DigitalHuman.vue` 内部增加表情状态机和嘴型视觉映射器，根据 `mouth`、`emotion`、`isSpeaking`、`isThinking` 选择透明局部层。
4. 图层配置统一保存画布尺寸、锚点及资源路径，素材更新不需要重新调整页面布局。

## 低成本素材产出

- 首选使用现有人物底图作为参考，以生成图工具产出透明或可抠图的局部嘴型、眼部与眉部变体。
- 若生成素材出现肤色边缘或定位差异，采用人工局部修边与统一画布对齐，不重新制作完整人物模型。
- 资产存储沿用 OSS `scenic-guide/digital-human/` 目录，开发阶段可使用版本化文件名避免覆盖当前可用素材。

## 验收标准

动态样片阶段：

- 可切换展示待机、思考和讲解状态。
- 讲解样例句中能够明显看到圆口、大开口、窄口及双唇闭合的差异。
- 表情与嘴型可同时出现，脸部、眼睛和嘴部无跳位。

小程序接入阶段：

- 语音播放、流式文本和现有 TTS 分段行为不回归。
- 长句播放期间表情稳定、口型不闪烁，讲解中允许自然眨眼。
- 微信开发者工具和真机均无图片错位、白边或性能明显卡顿。

## 边界与后续升级

第一阶段不引入 WebGL、Live2D SDK、云端视频流或新增付费 API，也不改变 TTS 响应协议。若分层样片通过但仍无法达到期望的头部运动表现，可在同一分层资产基础上进入 Canvas 轻变形增强版，而不推翻本方案。
