# DH_live 浅玉色舞台与微信式语音输入设计

## 目标

修复动态数字人舞台两侧景区背景与人物主体冲突的问题，并为 DH_live AI 导游页增加可用的微信式语音输入。识别结果只回填输入框，由游客确认后点击“输入”发送。

## 视觉

- 移除 `.avatar-stage` 的景区背景图片。
- 舞台统一使用浅玉色 `#dff4f1`。
- 保留人物画布 `object-fit: contain`，两侧自然显示浅玉色留白。
- 输入栏左侧使用麦克风图标；文字发送按钮文案改为“输入”。

## 交互

- 点击麦克风图标进入语音模式。
- 语音模式显示“按住说话”和键盘返回按钮。
- 按住开始录音，松开结束录音并发起识别。
- 手指向上滑动超过阈值时进入取消状态，松开后丢弃本次录音。
- 识别成功后将文字填入输入框并返回文字模式，不自动提交。
- 权限拒绝、录音过短、识别为空和网络失败均显示明确提示。

## 技术方案

- 浏览器端通过 Web Audio API 收集单声道 PCM。
- 浏览器端重采样并编码为 `16 kHz`、单声道、16-bit PCM WAV。
- `backendClient.mjs` 新增 `recognizeAudio(blob)`，以 `multipart/form-data` 上传到现有 `/tourist/voice/asr`。
- 复用现有后端 `ASRService` 与 DashScope Paraformer，不新增后端接口和付费依赖。

## 验证

- Node 单元测试覆盖 WAV 编码头、16 kHz 参数、ASR 上传和视觉契约。
- 原型完整测试通过。
- 后端 ASR API 测试通过。
- Playwright 移动端截图确认浅玉色舞台和输入栏布局。
